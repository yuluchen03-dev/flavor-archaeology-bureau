### 🔴 P0-1 后端 Docker 镜像 COPY 路径错误 → 容器无法启动

- **模块**：部署（`backend/Dockerfile`）
- **复现**：
  1. 阅读 `backend/Dockerfile`：
     ```
     WORKDIR /app/backend            # 第7行
     COPY backend/package*.json ./   # 第10行
     RUN npm ci --only=production
     COPY backend/src ./backend/src  # 第16行  ← 目标= /app/backend/backend/src
     CMD ["sh","-c","npm run db:migrate && npm run db:seed-if-empty && npm start"]  # 第33行
     ```
  2. `npm start` = `node src/app.js`（`backend/package.json`），工作目录 `/app/backend`，因此需要一个位于 **`/app/backend/src/app.js`** 的文件。
  3. 但 `COPY backend/src ./backend/src` 相对 `WORKDIR /app/backend` 解析，源码落到 **`/app/backend/backend/src/app.js`**。
- **期望**：容器启动后 `/app/backend/src/app.js` 存在，`node src/app.js` 成功。
- **实际**：`node src/app.js` → `Error: Cannot find module '/app/backend/src/app.js'` → 容器退出 → healthcheck 失败 → 依赖 `condition: service_healthy` 的 frontend 永不启动。
- **证据**：
  - 静态判定（Dockerfile 第 7/16/33 行 + package.json `start` 脚本）。
  - **`backend/src/scripts/__tests__/containerStartup.test.js:16` 反而断言了这个错误形态**：`expect(dockerfile).toMatch(/COPY\s+backend\/src\s+\.\/backend\/src/)` → 测试「通过」但把 bug 固化，属**假阳性测试**。
  - 变更前 `COPY backend/ .` 是正确的；本次「修复」引入了回归。
  - ⚠️ **未执行镜像构建**：本机 Docker daemon 未运行（`open //./pipe/dockerDesktopLinuxEngine: The system cannot find the file specified`），无法运行级实证。该判定为**高置信静态判定**。
- **修复建议**：`COPY backend/src ./src`；同步修正 `containerStartup.test.js` 断言为 `/COPY\s+backend\/src\s+\.\/src/`；并在 CI 增加 `docker compose build && docker compose up -d && curl /health` 的真实启动校验（注意见 P2-6）。

### 🟠 P1-4 大输入触发 `spawn ENAMETOOLONG` → `/api/analyze` 返回 500

- **模块**：后端桥接（`PythonBridge`）
- **复现**（服务实测）：
  ```bash
  # 阈值扫描（服务 PID 存活，逐档测试）
  content=1000  chars -> HTTP 200
  content=8000  chars -> HTTP 200
  content=20000 chars -> HTTP 200
  content=30000 chars -> HTTP 200
  content=50000 chars -> HTTP 500   ← 断点
  ```
  服务日志：`分析错误: Error: spawn ENAMETOOLONG ... at PythonBridge.call (src/services/PythonBridge.js:28:22)`
- **期望**：超长输入返回可控的 400/413，或经 stdin 传递被正常处理。
- **实际**：`PythonBridge.call` 把 JSON 作为**命令行参数**传给 Python（`spawn(PYTHON_BIN(), [wrapper, action, inputJson])`），超过 OS 命令行长度上限即失败：Windows≈32KB，Linux `MAX_ARG_STRLEN`=128KB。而 `express.json({limit:'10mb'})` 允许 10MB，形成**约 32KB~10MB 的失败窗口**。
- **证据**：见上方扫描 + `/tmp/be.log` 堆栈；`node_modules/raw-body` 同时确认 10MB 上限（>10MB → 413，见 §3）。
- **修复建议**：改为 stdin 传参（`spawn` 后 `stdin.write(inputJson)`），并给 `content`/`clue` 增加显式长度上限与 400 提示。

### 🟠 P1-5 `Dish.search` LIKE 通配符未转义（可全表扫描）

- **模块**：后端模型（`backend/src/models/Dish.js:37-41`）
- **复现**（服务实测）：
  ```
  GET /api/recipe/search?keyword=%E8%9F%B9 (蟹) -> 200，返回含"蟹酿橙"的匹配行
  GET /api/recipe/search?keyword=%25  (%)     -> 200，返回全表（东坡肉等全部菜品）
  ```

- **修复建议**：对 `keyword` 转义 `\ % _`（并配套 `ESCAPE`），或改用参数化 + 预设白名单。
